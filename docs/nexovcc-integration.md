# 环球卡台接入

按用户提供的 `nexovcc-integration.md`（2026-09-24）接入，仅用于当前 merge 项目。环球使用登录态 Web API，并非 EJH 的 Key/Secret 认证。

## 使用入口

1. 左侧 **EJH 卡台 → 环球卡台**：进入“配置与模板”，填写环球登录账号、密码、资金密码；绑定了谷歌验证时填写 Base32 验证密钥。
2. 保存并测试连接，随后同步产品和卡片。选择产品/BIN，保存开卡金额及费用预留模板。
3. **Pro 管理 → Pro 全自动配置 → 银行卡与补卡**：选择“环球”，设置是否无卡时自动开卡、环球模板、每日张数和充值金额预算。切换卡台保留两家的独立配置。
4. 手动开通可以选择已有卡；全自动、定时开通和自动补货使用所选卡台的可用卡，最早开出的优先。原账号的有限重试沿用原卡及流程。

环球页面提供卡片管理、账号回款、操作记录、配置模板，支持逐张批量开卡/销卡、进度、充值/提现、冻结/解冻、备注和单卡上限。成本统计、财务对账保持现有 EJH 范围。

## 确认与恢复

- 默认单卡成功开通上限为 1；单独修改上限不会清空历史付款次数。“一卡同时一个号”要求原账号回款确认后才释放占用。
- 账号移出仅标记“已申请待回款”。当前文档没有退款流水/金额查询接口，实际到账需在环球后台核实，再在账号回款中手动调整。恢复自动判断后继续跟随移出状态。
- 开卡固定 `open_num=1`，本地先落操作记录，再提交一次。超时、断连、5xx、无序列号进入待核实，禁止自动重复开卡。返回序列号但卡密未导入时，查询原卡继续导入。
- 资金操作与付款预留按物理卡互斥，未知付款不能用回款状态解除，也不能通过关闭“一卡同时一个号”绕过。
- 提现须留 1 USD，核实资金到账后释放提现操作。销卡前要求退款已到账、无未决订单/资金操作、卡余额不超过 1 USD；状态 4 是已销卡，不再重复提交。销卡后还会核实余额是否回到主账户。
- 充值、提现及不能确定的冻结结果，在操作记录中保留核实入口。人工修改保存依据、版本及审计历史。

## 运行依赖与接口边界

- 固定 `https://nexovcc.com`，POST JSON，不跟随重定向；Python `curl_cffi >= 0.16,<0.17`、`chrome150` 指纹。
- 账号密码登录，按响应要求完成 RFC 6238 TOTP；缓存 `user_id` 和 `VCC-Web` 20 分钟，提前 90 秒刷新。仅业务码 50001/50008/50009 自动重新认证并重放一次。
- 产品和卡列表每页 100 条，最多 100 页，发现重复分页或未知结构报错。兼容实际空卡账户返回的 `list: null, total: 0`；缺少总数或总数非零时仍报错，避免把异常响应当成空列表。仅产品状态 1 可用；卡状态仅确认 1 正常、4 已删除，其余保守不可分配。
- 登录凭据、资金密码、TOTP 和卡密在库内加密。普通列表不返回完整卡号/CVV；卡密需登录后单独查询，页面 30 秒隐藏。会话 Cookie 只保存在运行时。
- 上游若缺少开卡时间，页面显示“—”，不把导入时间假称开卡时间。
- 文档中的 `/api/admin` 以及 stock/养号池规则属于来源项目，不作为本 Space 的上游端点。

## 本地验证

已通过前端类型检查与构建，以及 Pro/EJH 相关 Go 回归。环球使用注入模拟接口验证认证、TOTP、分页、金额、开卡未知结果防重放、物理卡并发预留、同账号同卡有限重试直至推送、手动回款状态、提现/销卡恢复和响应隐私。

本地预览地址 `http://127.0.0.1:18120`，使用独立的 `data/nexovcc-preview`。已使用保存的环球配置只读验证产品列表和空卡账户列表；真实开卡、退款和销卡尚未完成联调。
