# Pro 自动补货

与 Pro 管理同级的独立菜单，包含监控大屏、补货配置、决策与记录。“查看”打开详情弹窗，支持 Esc 关闭和焦点返回。原数量型定时任务的配置与计算公式保持原状，共享账号领取与卡片占用保护。

## 启用

1. 更新并部署 Space；数据库自动添加补货表，默认关闭、观察模式。
2. 在 Pro 管理配置 Sub2 推送、请求并发、开通工作并发、目标母号、供应商和卡片。
3. Sub2 开启实时监控即可，兼容 Qerkai-sub2api 现有接口，无需安装采集质量扩展。
4. 读取分组，单选推送目标中包含的监控组，使用不共享账号的专用组。
5. 先观察容量、消耗和实际就绪耗时，设置水位、批量、在途、预算、冷却，再切换自动执行。

后台达标后调用现有全自动 Pro：登录、付款、新授权、推送、额度巡检、合并及移出。浏览器关闭不影响运行。“立即评估”在自动模式下会执行符合规则的任务。同池旧定时任务仍会按原策略补货，页面提醒但不擅自关闭。

## 每日禁补时段

在“Pro 自动补货 → 补货配置 → 每日禁补时段”设置开关、开始时间和结束时间。默认关闭；时间为北京时间（Asia/Shanghai / UTC+8），不依赖服务器或浏览器时区。支持同一天和跨午夜，例如 23:00～07:00；包含开始、不包含结束。启用时要求合法的 HH:mm，开始与结束不能相同，全天暂停请关闭自动补货总开关。

禁补期间继续采集、更新预测、记录决策和跟踪在途，但时间、并发、空组启动、最低备用、强制合并前接替与紧急排队均不能新增补货；“立即评估”也遵守此限制。决策、事务预留和最终派发分别检查当前时间，防止采集或排队期间跨入禁补窗口。已预留但未启动的任务在监控轮次中撤销，释放账号与预算；已启动的登录、开通、推送、原订单核验及后续流程继续执行。

结束时间后的下一轮检查，按新快照重新计算缺口，仍应用批量、冷却、在途、预算及失败保护，不积攒或一次性补齐禁补期间需求。大屏显示当前禁补状态，历史决策保存当时的配置及禁补原因。禁补仅限制 Pro 自动补货，不影响原定时任务或手动流程。

## 决策和到货延迟

时间不足、持续并发、最低备用、空分组启动与强制合并前接替独立判断，净缺口取最大值，再应用批量、在途、数量、预算、池上限与熔断。最低备用和空分组启动默认均为 0，保持已有配置行为。

“补货配置 → 补货数量 → 空分组启动补货数量”用于空池启动，0 关闭。只有账号和并发采集成功、快照有效且实际组成员为 0 时触发；组内有禁用、冷却或无额度账号不属于空组。无需等待额度样本或并发连续确认。设置 3 且同组已有 2 个在途时仅建议再补 1；登录、开通、待推送、结果未知和超时无 ETA 的任务均扣除，不能因尚未入组重复开通。

仅由空组规则触发时，不按普通最小批量向上取整（设 1 就按 1 计算），仍受每批最多、工作并发、最大在途、账号池、小时／日数量、预算、冷却及熔断限制。多个规则同时触发仍取最大缺口。观察模式只给建议；启用自动执行后才调用全自动 Pro。

本轮已原子预留的空组启动批次按工作并发逐个执行，首个账号入组不会取消本批剩余预留；采集异常暂停派发，配置变更或手动暂停会撤销未提交预留。组内有账号后，空组规则不再新建补货任务，因此不会持续维持固定数量。设置数量大于每批上限时，本轮只预留上限内数量；以后仅在仍为空组且冷却结束时重新计算缺口，不保证非空后继续补到启动数量。

状态为预留、启动确认、全自动执行、已推送待核验、就绪。逐号核验 Sub2 真实 ID、原分组、模型和可调度状态；无需等待整批或额度接口。已启动不等于当前容量，仅可信 ETA 的在途进入未来供给。

预计就绪覆盖工作排队、登录、开通、授权、推送和监控核验。历史足够时采用 P90，并按最新阶段的历史剩余耗时更新；不足时使用回退值。ETA 锚定原阶段时间，不随每轮检查向后漂移。超时任务保留在途但不承诺未来容量。提前补货取配置水位与保守到货时间加余量中的较大值。

新快照仍有缺口且冷却结束就继续补，不要求先恢复正常。紧急账号排队可缩短冷却，但不能绕过硬上限。流量下降只撤销尚未提交的多余预留；已付款继续核验原订单。付款成功但授权中断时按原重试限制恢复登录和授权，不重复购买。结果未知保留订单、预算及在途，在 Pro 管理核验原订单。

## 预计支撑时间与推送时限

监控大屏的预计支撑时间只使用 Sub2 监控组返回的账号、同套餐同窗口额度、消耗速度、重置、账号到期和并发数据。当前支撑时间不包含未就绪任务，不受 Pro 推送时限、开通供应商配置影响。以 15 秒步长估算首次供给缺口；套餐混用、窗口不同或样本不足时暂不可估。净补货需求计算可另外考虑套餐兼容且 ETA 可信的在途。

Pro 管理新增“推送时限”列：已开启及保存的分钟数、未开启、历史未知。新账号开始开通流程时保存当时开关和分钟数；仅首次成功推送开始倒计时，失败不开始，重推不重置。后续全局调整只影响新账号。历史账号没有保存该字段时不推断、不套用当前全局值，显示未知，不自动产生强制合并期限或提前补货需求。账号凭据更新及迁移保留已保存策略。

## 强制合并前提前补货

在原“补货配置”内与时间和并发规则并列设置，默认关闭、阈值 15 分钟。扫描当前监控组的全部账号；只统计通过 EJH 卡成功开通、已成功推送且仍可调度的 Pro 账号。已合并、已移出、已删除、未开通、时限未开启或记录未知的账号排除。

每号剩余分钟=max(0, 首次成功推送时间+账号保存的时限−当前时间)，平均值=剩余分钟总和÷有效账号数。平均值严格低于阈值才独立触发，不需要额度或并发规则同时满足。接替需求取逐号低于阈值的账号数，扣除已经关联的接替任务；与其他净需求取最大值，仍遵守批量、冷却、在途、预算及失败保护。建议阈值大于开通到可用耗时加缓冲。

每个原账号生命周期只关联一个接替任务，先关联目标一致的已有在途，再原子预留新任务。未知付款保留占用；确认失败或取消后才重新计算。重启以及 48 小时后仍保留就绪接替关系。新号成功推送且经 Sub2 核验可调度才算就绪。平均值回升或老号离组不会取消已安排的接替；配置变化、关闭规则或暂停仍会撤销未提交任务。

大屏“预计支撑时间”右侧显示平均剩余分钟、参与数、临期数、待补数、接替中和就绪数，并可展开逐账号倒计时。未开启及未知数量单列；采集不可用时隐藏旧统计，不用旧数据触发开通。

## Sub2 采集与故障恢复

Space 使用原生账号列表和并发接口，校验快照时效、分页完整性、组成员、容量及负载必要字段。`quality`、`load_known` 为可选增强信息，缺少时允许使用完整的原生数据；若明确报告采集失败，仍暂停新增。合法空组和零负载不会被当成采集失败。

请求失败、超时、关键字段缺失、快照过期或跨接口数据不一致时暂停新增，保留最近有效数据及其时间戳供查看，不用旧数据开通。总开关和运行模式保持不变，后台在每轮检查结束后等待配置的“并发检查周期”再重试；成功后自动恢复正常规则判断，连续压力确认重新积累，仍遵守冷却、预算和在途限制。已提交任务继续按原全自动流程执行和跟踪。

页面异常时显示“立即重试”，可主动发起一次新采集；成功才恢复判断，失败继续暂停并显示原因。已有采集或配置更新在进行时，提示稍后重试，不将旧数据冒充本次成功。手动关闭的总开关不会因重试成功而重新开启。额度独立采集仍按额度刷新周期运行，缺少可信额度样本时仅停用时间预测，并发规则仍可独立生效。

原生接口若将内部采集错误返回为正常的 0，Space 无法完全识别。历史质量扩展补丁仅作可选参考，不是启用前提，本次不修改或部署 Sub2。共享组账号及大面积账号异常仍按既有规则处理。

## 持久化及预算口径

SQLite 原子预留账号、预算与决策，派发前 CAS 领取；付款走原幂等机制。重启恢复跟踪。已提交任务保存加密原推送目标，配置变化仍核验原连接及组。重新导入凭据保留本机归属，跨服务器迁移不携带外部补货锁，仍检查原下游身份。适用于现有单进程部署，不支持多实例共享同一 SQLite 同时调度。

金额按配置的每号保守成本预留记账，不是供应商实付账单，也不包括手动和旧策略支出。结果未知跨日仍占用预算；已提交失败成本保守保留，未提交撤销释放。卡片单号占用、累计开通上限及付款防重仍走原机制。

额度由独立 4-worker 队列采集，不阻塞并发采样；大池整轮刷新可能超过配置周期，过期样本不参与时间决策。决策按变化或每 30 秒存档，配置保存及熔断重置也留记录。保留天数仅清理决策快照；任务和订单保留用于防重。

## 验证

覆盖双规则取最大值、批量硬上限、在途冷却、提前到货缺口、额度重置和套餐变化、合法零负载与缺失过期数据、上游异常、逐号就绪、付款后恢复、未知结果找回原订单、原子领取预算、重启和迁移。浏览器验收使用本地假数据，不产生真实订单。
